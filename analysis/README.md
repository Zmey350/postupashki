# Аналитика исходных продаж и исследовательские расчёты

Этот модуль сохраняет воспроизводимую аналитику предоставленного CSV и исследовательские проверки. Оперативная БД, дашборд и ML живут в других частях общего проекта. Общие определения заказов, пакетов, повторов, денежных сумм, ROMI и границ данных — только в [основном README](../README.md).

## Статус

| Компонент | Статус | Что готово и что осталось |
|---|---|---|
| EDA исходных продаж | **Реализовано и проверено** | Повторно рассчитаны аудит качества, пакеты, повторы, дни, ISO-недели и продукты. Вход — реальный CSV владельца. |
| Исторический backtest | **Реализовано и проверено** | Шесть методов, временные окна и последняя отложенная неделя. Выбранная модель проиграла baseline; будущая точность не подтверждена. |
| Восстановленная маркетинговая история | **Реализовано частично** | Даты/метаданные из реального HTML и ручная разметка сверены. Полноты истории, содержимого медиа и реестра внешней рекламы нет. |
| Исследовательская атрибуция | **Реализовано частично** | Пять правил и пять окон исполняются; содержательный результат проверен на синтетике. В реальном CSV нет индивидуальных касаний и затрат: ROMI неизвестен. |
| Экспериментальный калькулятор | **Реализовано частично** | Рандомизация, анализ всех назначенных участников и интервал проверены на синтетике; реальных исходов нет. |
| Реальный A/B и причинная оценка рекламы | **Только спроектировано** | Есть протокол и расчёты сценарной мощности; нужны управляемая аудитория, контроль до контакта, назначения и полные исходы. |

## Быстрое воспроизведение

Команды выполняются из корня проекта на Python 3.11+. Первые команды используют **только стандартную библиотеку Python**, без pip-зависимостей. Проверены с чистым выводом на оригинальном CSV владельца.

```bash
python -m analysis.reproduce --input "/path/to/base.csv" --out work/reproduced_analysis
```

Путь заменяется на CSV-экспорт листа «Данные» исходного `base.xlsx` с четырьмя полями. Сам `.xlsx`, другие листы и формулы книги нам не предоставлены. Исходный CSV и Telegram HTML в публичный проект не входят. При отсутствии оригинала можно просмотреть уже проверенные агрегаты в `data/public/`; это не синтетическая замена исходника.

`reproduce` рассчитан на исходный срез 04.08–10.09.2026: маркетинговые окна и исследовательская атрибуция привязаны к этому заданию. Для нового периода следует начать с отдельного EDA, а затем пересмотреть календарь и протокол, не отключая проверки исходного среза.

Единый источник итоговых аналитических чисел — `data/public/metrics.json`. Чтобы обновить поставляемые агрегаты после согласованной замены источника, используйте `--out data/public` и затем пересоберите итоговые документы. В исходном срезе получены 795 строк, 606 покупателей, 628 предполагаемых заказов и 5 904 671,67 ₽. Подробные интерпретации — [выводы и гипотезы](conclusions.md).

## Отдельные команды

```bash
# Агрегаты без индивидуальных покупок; работает и с другими периодами
python -m analysis --input "/path/to/base.csv" --out work/eda

# Backtest и прогноз; минимум 28 последовательных наблюдаемых календарных дней
python analysis/forecast.py --input "/path/to/base.csv" --out work/forecast

# История по предоставленной разметке постов + исходным продажам
python analysis/marketing/analyze_history.py --input "/path/to/base.csv" --out work/marketing

# Исследовательское сравнение пяти атрибуций; индивидуальные реальные продажи не выгружаются
python analysis/attribution/compare_attribution.py --input "/path/to/base.csv" --out work/attribution

# Прежний локальный движок отдельно: полностью синтетический пример
python analysis/attribution/engine/mvp.py --db work/research.sqlite3 demo --out work/research_demo

# Предложенные бюджетные лимиты и гипотетические размеры выборки
python analysis/budget.py --metrics data/public/metrics.json --out work/budget

# Импорт пользовательского публичного Telegram HTML
python analysis/marketing/import_html.py "/path/to/messages.html" "/path/to/messages2.html" --channel postypashki_old --from-date 2026-07-28 --to-date 2026-09-11 --out work/imported_posts.json

# Исполняемая демонстрация нормализации JSON-экспорта
python analysis/marketing/normalize_export.py analysis/marketing/demo_export.json --channel synthetic_demo --provenance synthetic --out work/imported_demo.json
```

Импорт HTML извлекает метаданные, а эвристические теги JSON — лишь кандидаты для ручной проверки. Эти команды не запускают Telegram-бота и не восстанавливают личные просмотры. `analysis/marketing/observations.json` — очищенная разметка предыдущего снимка с хешами текста и публичными ссылками. Если экспорт изменился, нужна новая проверка разметки; автоматическое переиспользование старых выводов недопустимо.

Старый движок `analysis/attribution/engine` нужен для сохранения воспроизводимости исследования пяти правил. Он использует отдельную SQLite для исследования, не заменяет операционную БД платформы. Его прямой `report` может сохранять подробные пути: такие локальные результаты не публикуют. Для безопасной публикации исторического исследования используйте `compare_attribution.py`.

## Калькулятор эксперимента и тесты

Только A/B-калькулятор и его тесты требуют SciPy; точная версия в `analysis/requirements.txt`.

```bash
python -m pip install -r analysis/requirements.txt
python analysis/experiment.py demo --out work/synthetic_experiment
python analysis/experiment.py analyze --assignments work/synthetic_experiment/assignments.csv --outcomes work/synthetic_experiment/outcomes.csv --config work/synthetic_experiment/config.json --as-of 2026-08-22T00:00:00+00:00 --out work/synthetic_experiment/recheck.json
python -m unittest discover -s analysis/tests -v
```

Проверены все 11 тестов финального модуля: сохранение денег при пакетах, повторные покупки, отсутствие клиентских строк в экспортируемых агрегатах, пропущенные дни, отсутствие утечки holdout, различие дневной/недельной ошибки, полнота экспериментального знаменателя, неизвестные расходы и зрелость окон.

Для будущего настоящего назначения:

```bash
python analysis/experiment.py assign --roster eligible.csv --config config.json --seed 123 --out assignments.csv
```

Формат и границы использования — [протокол](experiment_protocol.md). Реальных `eligible.csv` и `config.json` нет; последняя команда является шаблоном будущего запуска, а не заявлением о состоявшемся эксперименте.

## Результаты и ограничения

- `daily.csv`, `weekly.csv`, `products.csv`, `packages.csv`, `product_pairs.csv` содержат агрегаты без идентификаторов покупателей и точных времён покупок. Неполные граничные ISO-недели явно отмечены; неизвестная дата не превращается в ноль.
- `forecast/` содержит исторические прогнозы, ошибки шести методов и проекцию недели; это не ML-скоринг клиентов из `ml/`.
- `marketing/` содержит подтверждённый постами календарный контекст. Совпадение цены и состава с акцией не устанавливает источник или причинный эффект заказа.
- `attribution/` разделяет `real` и `synthetic`. 0% покрытия реальных источников означает нехватку данных, а не отсутствие пользы рекламы.
- `budget/` — предложенные лимиты и гипотетические параметры, не цены каналов и не рекомендации автоматически тратить деньги.
